Markdown 系统学习

Markdown 是一种轻量级标记语言，用纯文本表达标题、列表、链接、代码和表格，再渲染成 HTML。它是 README、技术文档、笔记、博客和协作平台的事实标准。Markdown 的语法很小，但不同平台的实现存在差异：理解 CommonMark 核心与 GFM 扩展的边界，能避免大量“我这里能显示、你那里不行”的问题。

纯文本CommonMarkGFM 可移植文档工程
难度：入门 → 熟练 规范：CommonMark + GFM 阅读时长：约 40 分钟

认识 Markdown

Markdown 由 John Gruber 与 Aaron Swartz 于 2004 年创建，目标是“让文档源码像纯文本一样易读，同时能转换成结构化的 HTML”。它不描述字体、颜色或布局，只描述结构：这是标题、这是列表、这是代码。

可读的源码

即使不渲染，纯文本本身也有清晰结构，适合版本控制与 diff。

平台无关

任何编辑器都能打开；可转换为 HTML、PDF、Word、幻灯片。

语法极简

核心语法十几分钟就能学会，其余靠约定与扩展。

实现有差异

CommonMark 是核心规范；表格、任务列表等属于扩展。

CommonMark 与 GFM

规范覆盖范围典型使用场景
CommonMark标题、段落、强调、列表、链接、图片、代码、引用、分割线等核心语法追求跨平台一致的文档
GFM（GitHub Flavored Markdown）CommonMark + 表格、任务列表、删除线、自动链接、脚注等GitHub、GitLab、许多笔记软件
其他扩展数学公式、Mermaid 图表、Front Matter、定义列表、警告块静态站点、Obsidian、Typora、文档平台
不要假设所有平台都支持扩展 表格、任务列表、删除线、脚注、数学公式并非 CommonMark 核心。发布到不同平台前，先用目标平台的预览确认；重要文档优先使用核心语法。

渲染流程

Markdown 源文件通常经过：解析 → 生成 AST → 转换为 HTML。不同解析器（markdown-it、CommonMark.js、Python-Markdown、pulldown-cmark）对边缘语法处理不同，所以“严格 CommonMark”与“某个平台方言”可能表现不一致。

Markdown 中的 HTML

Markdown 允许内嵌原始 HTML，用来补足 Markdown 不支持的布局或语义。但不同平台对 HTML 的过滤策略不同：GitHub 会清洗危险标签与属性，一些文档系统则完全禁用原始 HTML。

易错点与写作规范

问题原因 / 解决
#标题 不生效# 与文字之间必须有空格：# 标题。
段落被合并段落之间需要空行。
换行不生效行末加两个空格、反斜杠，或使用 <br>。
嵌套列表错乱子列表缩进 2–4 个空格，并与父项内容对齐。
--- 变成标题前面缺少空行，被当作 Setext 标题下划线。
表格不渲染表头与分隔行之间不能有空行；需要 GFM 支持。
表格内竖线破坏结构用 \| 转义，或放进行内代码。
代码块围栏提前结束代码内容含三个反引号时，外层改用四个反引号或波浪号。
列表中放代码块失败代码围栏要缩进到列表内容层级。
链接含空格/括号用尖括号包裹 URL，或对空格使用 %20。
强调不生效标记与文字之间不要有空格：**加粗** 而非 ** 加粗 **。
HTML 被过滤平台安全策略；改用原生 Markdown 语法。
中文标点紧邻链接自动链接可能把标点吞入；显式链接更稳妥。

写作规范建议

  • 一致的标记风格：无序列表统一用 -，强调统一用 **，不让风格随机变化。
  • 一行一句或短行：便于 diff 与评审；长段落可读性差。
  • 标题即目录：让标题能独立表达信息，不写“其他”“更多”。
  • 代码块标注语言：方便高亮、复制和检查。
  • 链接用描述性文字：避免“点这里”，利于无障碍与检索。
  • 图片写 alt：描述内容而不是文件名。
  • 表格只放短内容：长段落放回正文。
  • 先保证核心语法：跨平台文档谨慎使用扩展。
  • 在目标平台预览：发布前检查渲染差异。
README 的最小结构 项目名与一句话简介 → 功能特性 → 安装 → 快速开始 → 使用示例 → 配置 → 常见问题 → 贡献指南 → 许可证。保持简短，把细节链接到独立文档。
